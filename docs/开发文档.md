## 2. 技术方案定版（不用 Qt）

### 2.1 结论

| 层 | 选型 | 一句话理由 |
|---|---|---|
| 窗口 | **Win32 原生单 HWND 自绘控件树**（1 主窗 + N 个浮动面板窗 + 1 个拖拽预览分层窗） | 逐像素控制、无框架税 |
| 2D 渲染 | **Direct2D 1.1（`ID2D1DeviceContext`）+ DirectWrite + WIC** | 微软为 UI 设计的硬件加速 2D；抗锯齿/alpha/几何/图层齐全；底子是 D3D11 |
| 合成/动画 | **DirectComposition（DComp）** 用于浮动面板与动画层 | 面板飞入/归位/重排由 DWM 合成，不掉帧、不占 UI 线程 |
| 依赖 | **WIL**（`wil::com_ptr`，微软 header-only，MIT） | 免写 `Release()`；不引入框架 |
| 构建 | CMake ≥3.25 + MSVC（`/std:c++20`） | 标准做法 |
| 图标 | Fluent UI System Icons（MIT）→ SVG 路径 → D2D Geometry | 矢量缩放不糊 |

### 2.2 为什么不是别的

| 备选 | 否决理由 |
|---|---|
| **Qt**（用户已排除） | 框架自带窗口/停靠/样式体系，逐像素定制要跟它打架；产物体积大；许可证对分发不友好 |
| **WebView2 + HTML/CSS**（Monaco + Dockview） | 出活最快、视觉最现代，Dockview 直接给 VS 式停靠。**但不是 C++ 自绘**（用户明确要求 C++），高 DPI/输入法/拖拽手感/启动速度都不如原生，后期做表格化编辑器还得跨 JS↔C++ 边界 |
| WinUI3 / WPF | 需运行时/托管栈；自绘表格与流程线反而受限 |
| GDI / GDI+ | 无 GPU 加速、无抗锯齿、alpha 混合差；圆角/阴影/深色/高分屏全废 |
| DX12 | 游戏管线，自己管堆/fence/描述符；给 IDE 用是自找闪烁与 TDR。D2D 已在 D3D11 上，性能远超需求 |
| Skia | 跨平台强，但 Windows 上要自己解决合成/DPI/输入法，收益不如 D2D 原生 |

### 2.3 渲染架构（硬约束）

```
App(MainWnd)
 └─ UI Thread
     ├─ D3D11 Device ─→ D2D1 Device ─→ DeviceContext
     │                             └─→ DirectWrite Factory
     ├─ 每个顶层窗口(主窗/每个浮动面板)：
     │     DXGI SwapChain(FlipModel) + ID2D1Bitmap1 target
     ├─ 主窗内：所有面板画进同一个 target（脏矩形合批）
     ├─ 浮动面板：各自 HWND + 各自 swapchain，共享同一个 D2D Device
     ├─ 拖拽预览：WS_EX_LAYERED + WS_EX_TOOLWINDOW 独立小窗 + DComp visual
     └─ DComp: 浮动面板飞入/归位、面板重排过渡、提示气泡
```

要点：
1. **共享一个 D2D Device**，资源（画笔/字体/几何）集中缓存，key 含 `dpiScale`。
2. **脏矩形**：`InvalidateRect` 合并 → 一帧只画变化区域；拖分隔条时只重画两侧面板。
3. **动画**（重排/浮动飞入/折叠）走 `DCompositionAnimation`（CubicBezier/Spring），**不占 UI 线程**；纯 UI 内部动画（悬停/选中）用 100~160ms 定时器插值。
4. **文字**：`IDWriteTextLayout` 缓存（key = 文本 + 格式 + 最大宽 + dpi），不要每帧重新 layout。
5. **设备丢失**：所有 D2D 资源挂 `DeviceResources`；`D2DERR_RECREATE_TARGET` / `DXGI_ERROR_DEVICE_REMOVED` → 统一重建（字体格式可复用，位图/画笔重建）。
6. **垂直同步**：`Present(1,0)`；拖动等高频操作允许 `Present(0, DXGI_PRESENT_DO_NOT_WAIT)` 丢帧保跟手。

### 2.4 DPI 规格（硬约束）

| 项 | 要求 |
|---|---|
| 感知 | `SetProcessDpiAwarenessContext(DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2)` + manifest `PerMonitorV2` |
| 坐标 | 全部 `float` DIP（96 基准）；渲染前 `round(pos*scale)` 对齐物理像素 |
| 缩放事件 | `WM_DPICHANGED`：按 `lParam` 建议矩形改窗口 → 重建文字格式 → 重算布局 → 重设位图 |
| 跨屏拖动 | 浮动面板跨不同 DPI 显示器时按新窗口 DPI 重建 target，DIP 坐标不变 |
| 字体 | DirectWrite 回退链：`Segoe UI Variable Text` → `Segoe UI` → 中文 `Microsoft YaHei UI` |
| 图标 | 矢量几何（SVG path）优先；位图必须多尺寸（16/20/24/32/48/64） |
| 自绘标题栏 | `WM_NCCALCSIZE` + `WM_NCHITTEST` 必须正确（否则 150% 下拖不动窗口/双击最大化失效） |
| 验收 | 100%/125%/150%/200% 四档截图：无重叠、无半像素缝、文字锐利、拖动跟手 |

**实现现状（2026-11-09，GDI 自绘版）**

| 项 | 落地方式 |
|---|---|
| 感知 | `dpi_awareness_init()`：`GetProcAddress` 取 `SetProcessDpiAwarenessContext(PMv2)` → 失败退 `SetProcessDpiAwareness(2)` → 再退 `SetProcessDPIAware()`。不新增导入库，老系统不会因缺符号起不来 |
| 初始 DPI | `dpi_scale_at(pt)`：`MonitorFromPoint` → `CreateDC("DISPLAY", 设备名)` → `GetDeviceCaps(LOGPIXELSX)`。**不能用 `GetDC(NULL)`**（那永远给主屏/系统 DPI） |
| 全局系数 | `g_s = g_dpiScale × g_uiScale`；`S()/R()` 全走它，改一次全局重排 |
| 缩放事件 | `WM_DPICHANGED`：重算 `g_dpiScale`/`g_s` → `fonts_rebuild()` → 清 `g_logDx` → 按 `lParam` 建议矩形 `SetWindowPos` → 整窗无效重绘 |
| 分辨率变化 | `WM_DISPLAYCHANGE`：只收不放，窗口超出新工作区才挪/缩，然后重绘 |
| 诊断 | 环境变量 `IDE_DPI_LOG=<绝对路径>` 写 `aware= / STARTUP / DPICHANGED` 三类行（GUI 无 stderr） |

## 4. 停靠系统：VS 式可拖放停靠（本期必须做）

> v1 里曾建议"第一版不做自由停靠"，**用户明确要求必须做**，故本期按下面自研路线实现。C++/Win32 生态没有成熟且许可友好的 VS 式停靠库（Qt ADS / KDDockWidgets 绑 Qt，CodeJock 收费），自研反而最快。

### 4.1 布局模型：可拆分布局树（硬约束）

```cpp
struct DockNode {
    enum class Kind { Split, Tabs } kind;
    // Split
    Orientation orient;          // Horizontal(左右) / Vertical(上下)
    float ratio = 0.5f;          // 拖动分隔条修改
    std::unique_ptr<DockNode> first, second;
    // Tabs
    std::vector<PanelId> panels;
    PanelId active;
    std::string persistId;
};

struct Panel {
    PanelId id; std::string title; IconId icon;
    std::unique_ptr<Widget> content;
    enum class State { Docked, Floating, AutoHidden } state = State::Docked;
    RectD floatRect; Side autoHideSide;
};
```

操作原语（全部走命令、可撤销）：

| 操作 | 语义 |
|---|---|
| `SplitAt(target, zone, newPanel)` | 在 target 的 Tabs 节点按方位拆两侧（左/右→Horizontal，上/下→Vertical） |
| `MergeInto(target, panel)` | 并成同组 Tab（zone = Center） |
| `MoveToRootEdge(side)` | 拖到主窗边缘 → 在根上按方位新建分割 |
| `Float(panel)` | 变独立顶层窗口（新 HWND + swapchain），从树中摘除 |
| `DockBack(panel, target, zone)` | 浮动面板拖回 → Split / Merge |
| `AutoHide(panel, side)` | 收进左/右/下边缘隐藏条（hover 弹出，PIN 回来） |
| `ResizeSplit(nodeId, ratio)` | 分隔条拖动 |

### 4.2 拖放交互（按 VS 手感做）

1. **拖动源**：页签或面板标题栏；按下后移动 >4 DIP 才进入拖拽态（防误触）。
2. **预览**：半透明拖拽缩略条跟随鼠标，主窗进入"停靠预览模式"。
3. **罗盘（Dock Guide）**：鼠标进入任一 Tabs 组区域 → 在该区域中央画 5 区罗盘：中心方块（并入 Tab）+ 四边箭头块（左/右/上/下分割）。命中判定：边缘 25% 带 → 对应方向，中央 50% → Center（用鼠标到四边的最小距离更自然）。高亮 = `accent` 20% 填充 + 1px 描边；罗盘 180×180 DIP，淡入 100ms。
4. **窗口边缘**：拖到主窗边缘 20 DIP 内 → 整条边缘高亮 → 松手在该侧新建分割。
5. **拖出成浮动**：拖出客户区 >24 DIP → 显示浮动轮廓预览 → 松手创建浮动窗口（尺寸 = 面板当前尺寸 ×1.2，位置贴鼠标）。
6. **松手动画**：目标区 160ms 展开（`cubic-bezier(0.2,0,0,1)`）；浮动→停靠用 DComp 飞行归位 200ms。
7. **取消**：`Esc` 恢复原布局。
8. 本期只允许单面板拖动。

### 4.3 浮动面板

- 独立 `WS_OVERLAPPEDWINDOW`（自绘标题栏），各自 `PerMonitorV2`；共享 D2D Device，各自 swapchain。
- 标题栏拖到主窗罗盘 → 停靠回去；拖到屏幕边缘 → Windows Aero Snap（系统自带）。
- 关闭（×）= 隐藏并记住位置（不销毁）；可从「查看」菜单恢复。
- 记住位置/尺寸/显示器/DPI；恢复时显示器不存在则钳制到主屏。

### 4.4 自动隐藏

- 标题栏 `📌`：取消固定 → 滑出到最近边缘，留 4 DIP 把手。
- 悬停把手 300ms → 滑出（160ms）；离开 500ms → 收回。
- 收回时面板标题竖排显示（宽 28 DIP）。

### 4.5 持久化

- `%APPDATA%\<ProductName>\layout.json`：版本 + 树 + 每个浮动窗 rect + 主窗 rect + 主题。
- 加载校验：PanelId 不存在 → 丢弃节点；矩形超出所有显示器 → 钳制；DPI 变化按新 DPI 重算。
- 「查看 → 重置窗口布局」恢复默认。

### 4.6 本期验收清单

- [ ] 面板可拖到左/右/上/下/中 5 个位置，语义符合 VS
- [ ] 拖出成浮动窗、再拖回

## 5. 窗口设计器（本期主角）

### 5.1 定位

`design::FormDesignerSurface` 实现 `editor::IEditorSurface`，由 `DocumentHost`（文档页签容器）托管——与未来的代码视图是同级文档类型，本期只实现设计器。

### 5.2 数据模型

```cpp
struct ControlInstance {
    ControlTypeId type;        // "button","edit","label","groupbox","tabctrl"...
    std::string id;            // 控件名("按钮1")
    RectD bounds;              // 相对窗体客户区，DIP
    std::map<std::string, PropertyValue> props;   // 标题/字体/颜色/可视...
    int zOrder = 0;

struct FormDocument {
    std::string name;               // "Form1"

    GridSettings grid{8.0, true};
    bool snapToGuides = true;
    float zoom = 1.0f;              // 25%~400%
```

### 5.3 渲染层次（从下到上，硬约束顺序）

```
1) 画布外背景（bg.canvas）+ 窗体投影
2) 窗体矩形：填充 bgColor、1px 边框、不可拖动的窗体标题条
3) 网格点阵（zoom ≥ 60% 才画；间距 8 DIP × zoom；暗色 rgba(255,255,255,.04) / 浅色 rgba(0,0,0,.06)）
4) 控件（zOrder 升序；容器先自身再子控件并裁剪到容器客户区）
5) 悬停指示（1px accent 虚线，仅未选中时）
6) 选择框 + 8 个尺寸手柄（6×6 DIP，accent 填充 + 白描边；多选时最外层画总框）
7) 对齐参考线（拖动时出现，1px accent，横跨画布，两端小三角）
8) 框选矩形（accent 12% 填充 + 1px 虚线）
9) 标尺（上/左各 20 DIP，刻度 + 鼠标位置指示线 + 画布起点）
10) 画布状态浮层（"640 × 480 · 缩放 150% · 网格 8"）
```

### 5.4 坐标与缩放

- **设计坐标 = DIP，原点在窗体客户区左上**。缩放只影响显示：`screen = canvasOrigin + design * zoom`。
- 缩放 25%~400%，`Ctrl+滚轮` 以鼠标点为锚；`Ctrl+0` = 100%，`Ctrl+1` = 适应窗口。
- 画布大于视口时出滚动条；平移：空格+拖动 或 中键拖动。
- **手柄与选择框不随 zoom 缩小**（恒 6 DIP，命中 8 DIP），否则缩小后点不到。

### 5.5 选择与操作

| 操作 | 行为 |
|---|---|
| 单击控件 | 单选；属性框切到该控件；底部「事件」列出其事件 |
| Shift/Ctrl+单击 | 加选/减选 |
| 空白处拖动 | 框选（相交即选） |
| 单击窗体空白 | 选中窗体本身 |
| 拖动选中控件 | 移动（多选整体移动）；`Shift` 锁单轴；`Esc` 取消本次拖动 |
| 拖 8 手柄 | 缩放；`Shift` 等比；`Alt` 以中心缩放；最小 4×4 DIP |
| 方向键 | 移动 1 DIP；`Shift+方向` 10 DIP |
| `Delete` / `Ctrl+A` | 删除选中 / 全选 |
| `Tab` / `Shift+Tab` | 按 z 序轮换选中 |
| `Ctrl+↑/↓` | z 序上下移 |
| 双击控件 | 触发默认事件（本期：状态栏提示 + 输出日志） |
| 右键 | 剪切/复制/粘贴/删除/置顶/置底/锁定/属性 |

### 5.6 吸附与对齐线

- **网格吸附**：拖动/缩放时左上与右下对齐 `round(v/grid)*grid`（网格 4/8/16/关，工具条可改）。
- **对齐线**：与其它控件的 左/右/上/下/水平中/垂直中 比较，差值 <6 DIP 即吸附并画线。
- **间距提示**：与最近两兄弟间距相等时显示间距数字（本期用 accent 色）。
- **优先级**：对齐线 > 网格；按住 `Alt` 临时关闭全部吸附。
- 拖动中状态栏实时显示 `X, Y` 与 `W × H`。

### 5.7 从组件箱拖放（关键链路）

```
组件箱(ToolboxPanel)  ──拖动──▶  设计器(FormDesignerSurface)
 1. 按下并移动 >4 DIP → 启动拖拽源
 2. 数据：自定义格式 "ELANG/COMPONENT" = 组件类型 ID（另有 CF_UNICODETEXT 降级）
 3. 进入画布 → 绘制"放置预览"：默认尺寸矩形（accent 20% 填充 + 描边 + 名称标签）
 4. 预览位置 = 鼠标 - 默认尺寸/2，并按网格/对齐线吸附
 5. 松手 → 创建 ControlInstance（z 序最高）→ 自动选中 → 属性框联动 → 输出面板记录
 6. 拖进容器控件（分组框/选择夹页）内部 → 成为其子控件，坐标转相对
 7. 入撤销栈
```
拖拽幽灵图 = 组件图标 32×32 + 名称，透明度 70%，偏移 (+12,+12)。

## 10. 代码编辑器（**本期不做，只留接口**）

### 10.1 为什么不是文本编辑器
易语言代码视图是**结构化表格**：一行 = 一条语句，行内按「流程列 / 命令单元格 / 参数单元格 / 备注列」切分，列宽跨行对齐；`如果/循环/判断` 用缩进与流程连线表达嵌套。本质是**语句树 + 参数槽**的投影。

### 10.2 四大难点
1. 列宽自适应 + 跨行对齐（受折叠/字体/内容宽度影响）
2. 行高不一致 + 虚拟滚动（几千行，折叠块高度变化）
3. 流程线绘制与状态同步（缩进竖线/拐角、块配对高亮、折叠、滚动重绘）
4. 行内编辑 + 语句块拖拽移动（每次改动重算列宽/流程线/索引）

### 10.3 接口（本期定好，避免返工）

```cpp
struct IEditorSurface {
    virtual void Attach(HWND host, gfx::D2DContext* gfx) = 0;
    virtual void SetDocument(DocumentId id) = 0;
    virtual void OnResize(const RectD& r) = 0;
    virtual bool OnInput(const InputEvent& e) = 0;
    virtual void Paint(gfx::RenderCtx& ctx, const RectD& dirty) = 0;
    virtual bool CanClose() = 0;
    virtual ~IEditorSurface() = default;
};
```
`FormDesignerSurface`（本期）与未来的 `CodeSurface` 都实现它，由 `DocumentHost` 统一托管。

### 10.4 下一阶段候选（**尚未决策，禁止提前实现**）
| 路线 | 优点 | 风险 |
|---|---|---|
| 自研 D2D 整行渲染 + 自绘输入 | 对齐/性能/像素控制最好，最接近易语言原实现 | 光标/选区/IME/撤销全自己做 |
| WebView2 + Monaco/CodeMirror | 编辑内核白送 | 表格化逆着文本模型做，列对齐/流程线靠装饰层硬凑 |
| 虚拟表格库 + 自绘单元格 | 虚拟化现成 | 行内编辑/流程线/块拖拽仍自研 |

**开工前先做 200~300 行 spike**，只验四件事：1000 行虚拟滚动不掉帧 / 三层嵌套流程线+折叠+配对高亮 / 单元格行内编辑+回车插行+列宽即时重算 / 拖拽语句块联动更新。四条全过再定架构。

```python
# pip install pywin32；只用 Win32 API，不注入不 hook
import win32gui
def dump(hwnd, depth=0):
    cls, txt = win32gui.GetClassName(hwnd), win32gui.GetWindowText(hwnd)
    print("  "*depth, hex(hwnd), cls, repr(txt), win32gui.GetWindowRect(hwnd))
    win32gui.EnumChildWindows(hwnd, lambda h,_: (dump(h, depth+1), True)[1], None)
```

## 19. 模块化与 AI 可操作层（UiBridge）— 硬约束

> 用户要求：**模块化开发，所有地方都留出接口，让 AI 能操作整个 IDE 的 UI**。
> 这一章不是"建议"，是验收项。做不到，后面的 Part 验收就没法自动化。

### 19.1 三条铁律

| # | 铁律 | 含义 | 违反的后果 |
|---|---|---|---|
| 1 | **接口先行** | 每个模块先交头文件（纯虚接口 + 数据结构），再交实现。头文件里不出现任何 UI 框架类型（HWND/ID2D1 除外且只允许在该模块内部） | 模块之间长成蜘蛛网，改一处崩三处 |
| 2 | **无隐形路径** | 界面上任何用鼠标/键盘能做的事，**必须**存在等价的 `Command` 或 `UiBridge` 方法。禁止"这个行为只写在鼠标事件里" | AI 无法驱动、无法回归测试、无法自动验收 |
| 3 | **单向依赖** | `platform ← gfx ← ui ← dock / design ← app`。下层不认识上层；跨模块通信只走 `EventBus` 与 `CommandRegistry`，禁止直接调别的模块私有实现 | 循环依赖，编译爆炸 |

补充：**模块可单独编译**（每个模块一个静态库 target），`app` 只做装配。任何模块不得包含 `app` 的头文件。

### 19.2 模块边界与接口契约

| 模块 | 对外头文件 | 暴露的能力 | 允许依赖 |
|---|---|---|---|
| `platform` | `IWindowHost`、`IDpiContext`、`IInputSource` | 建窗、消息循环、DPI 查询、原始输入事件 | Win32 |
| `gfx` | `IRenderCtx`、`IDeviceResources`、`ITextCache` | 开画、画几何/文字/图片、文字度量、设备丢失恢复 | D3D11/D2D/DWrite/WIC/DComp |
| `ui` | `IWidgetTree`、`IFocusManager`、`IWidgetFactory` | 控件树装配、命中、焦点、控件树快照 | gfx |
| `theme` | `IThemeManager` | 取令牌、切主题、订阅变更 | gfx |
| `command` | `ICommandRegistry` | 注册/执行/查询命令（enabled/checked）、快捷键表 | 无 |
| `dock` | `IDockHost` | 布局树读写、Split/Merge/Float/AutoHide、快照/恢复 | ui, command |
| `design` | `IFormDesigner` | 表单文档、选择集、增删改控件、吸附、撤销、快照 | ui, command |
| `editor` | `IEditorSurface` | 文档渲染与输入（设计器/未来代码视图都实现它） | gfx, ui |
| `app` | `IAppFacade` + `IUiBridge` | 装配、生命周期、**对外自动化通道** | 全部 |

```cpp
// app/IAppFacade.h —— 进程内唯一门面，所有对外能力都从这里进
struct IAppFacade {
    virtual ICommandRegistry& Commands() = 0;
    virtual IWidgetTree&      Widgets()  = 0;
    virtual IDockHost&        Dock()     = 0;
    virtual IFormDesigner&    Designer() = 0;   // 当前活动设计器（无则抛 NoActiveDocument）
    virtual IThemeManager&    Theme()    = 0;
    virtual IEventBus&        Events()   = 0;
    virtual std::string       SnapshotTreeJson(int depth) = 0;
    virtual ~IAppFacade() = default;
};
```

### 19.4 传输、安全、线程（硬约束）

1. **本机通道优先命名管道**：`\\.\pipe\<ProductName>-bridge`，JSON-RPC 2.0，一行一条消息（`\n` 分隔）。
   可选再开 HTTP：`127.0.0.1:<随机端口>`，端口与 token 写入 `%APPDATA%\<ProductName>\bridge.json`。
2. **只绑 loopback**（`127.0.0.1` / 命名管道）；**绝不** `0.0.0.0`。产品本身不联网（这是本地进程间通信，无外网行为）。
3. **鉴权**：每次启动生成 32 字节随机 token 写 `bridge.json`（当前用户权限）。所有 `ui.*` 写类方法与 `ui.script.*` 必须带 token；只读方法同用户进程可免。
4. **线程模型**：任何调用都 `PostMessage` 到 UI 线程执行，调用方阻塞等结果（默认超时 5s，超时返回 `E_TIMEOUT`）。**禁止**在非 UI 线程直接碰控件或布局。
5. **日志**：每次调用写 `bridge.log`（时间 / 方法 / 参数摘要 / 结果 / 耗时 / 是否成功）。排查"AI 说改了其实没改"靠它。
6. **不允许**绕过命令与模型层：bridge 只能调 `IAppFacade` 暴露的方法，不能反射式改控件字段。这样一切操作可撤销、可重放、可审计。
7. **崩溃保护**：bridge 调用异常必须被捕获并返回 `E_INTERNAL` + 栈摘要，不允许打崩主进程。

### 19.8 反模式（明确禁止）

- ❌ 把行为写在鼠标事件里、没有命令入口（例：面板关闭只处理了标题栏 ×）。
- ❌ 用 `Sleep` 做"等界面就绪"（必须用 `ui.waitFor`）。
- ❌ 控件 path 用指针/地址（重启就变）。
- ❌ bridge 直接改控件字段（必须走命令/模型，保证可撤销）。
- ❌ 为省事把某模块做成"只有一个大文件 + 全局函数"（失去可测试性）。
- ❌ 先写实现后补接口（接口会变成"实现的复印件"，起不到解耦作用）。

## 20. Part-by-Part 增量交付协议 — 硬约束

> 用户要求：**一个一个写好，先做窗口，再做菜单，再做工具栏……每一步我确认可以了，再做下一个部分。**

### 20.1 铁律

1. **一次只做一个 Part**。做完 → 交付 → **等用户明确说"可以"** → 才允许开始下一个。
2. 未收到确认前，**禁止**开始下一个 Part、禁止"顺手"实现后续内容、禁止跨模块重构。
3. 某个 Part 必须依赖后续能力才能完成时：先只补那**一个接口**（空实现），在交付说明里写明"为完成本 Part 需要 X 接口，已留空实现"，不要顺手把它实现完。
4. 每个 Part 结束时 Git commit + tag（`P0`、`P1`…），并在 `docs/parts.md` 勾选进度。
5. 引入新依赖、改设计令牌、改本文档规格 —— **必须先问用户**，不许先做后说。

## 21. 「夹」（Tool Window）规格：术语、三态显隐、页签位置

> 用户截图提问：底部那排 `支持库 / 程序 / 属性 / AI` 叫什么？—— 易语言里这块叫「**夹**」，具体是「**工作夹**」；那排是它的**页签条**。
> 证据：`易语言安装目录\e.exe` 的 GBK 字符串里就写着 `左侧支持库工作夹`、`工作与状态组合夹`、`状态夹`、`工作夹`、`组件箱`。

### 21.1 术语对照（写进代码与界面文案）

| 易语言术语 | 含义 | VS 术语 | 本产品用词 |
|---|---|---|---|
| **夹** | 可停靠的面板容器 | Tool Window | 工具窗口（面板） |
| **工作夹** | 左侧主面板（含 程序 / 支持库 / 属性 / AI 页签） | Solution Explorer 所在的 Tool Window | 工作夹 |
| **页签** | 夹内同组的多个面板标签 | Tab / Tab Strip | 页签 |
| **状态夹 / 输出夹** | 底部面板 | Output / Error List | 输出 |
| **组件箱** | 控件工具箱 | Toolbox | 组件箱 |
| **程序数据** | 工作夹「程序」页签内的树 | Solution Explorer 树 | 程序树 |
| **工作与状态组合夹** | 左侧工作夹 + 底部状态夹的组合布局 | 布局预设（Layout） | 布局预设 |

> 设计决定：**「属性」在本产品里做成右侧独立工具窗口**（VS 习惯，常驻更有用），但页签机制与「工作夹」完全一致——同一个夹里可以叠多个页签，位置由布局决定。想还原易语言做法（属性塞进工作夹同一排页签）也只需改 `layout.json`，不需要改代码。

### 21.2 三态显隐（硬约束，用户明确要求"点击显示、再点击隐藏"）

每个工具窗口有三种状态，可随时切换、可持久化：

| 状态 | 表现 | 进入方式 |
|---|---|---|
| **Docked（固定）** | 常驻在布局树里的位置 | 默认；点页签/标题 |
| **AutoHidden（自动隐藏）** | 收起为边缘一条把手（4 DIP），悬停 300ms 弹出，离开 500ms 收回 | 标题栏 `📌` 取消固定 |
| **Hidden（关闭）** | 完全不可见 | 标题栏 `×` / 活动栏再点一次 |

**点击显隐（用户要求的主交互）**：左侧/右侧各有一条**活动栏（Activity Bar，宽 40 DIP）**，竖排在窗口最外沿：

- 每个工具窗口一个图标（16/20 DIP，单色，激活时 `accent` + 左侧 2 DIP 高亮条）。
- **点一次 → 显示该工具窗口；再点一次 → 隐藏**（若它是当前唯一可见的右侧面板，则整列收起，中央区扩张）。
- 图标 hover 显示名称气泡；`Ctrl+Alt+<数字>` 直达。
- 活动栏本身可隐藏（`查看 → 活动栏`），隐藏后只能靠菜单/快捷键打开面板。
- 活动栏与工具窗口之间的边界可拖动；活动栏可配到窗口左侧或右侧（默认左侧）。

与 VS 的对应关系：这就是 VS Code 的 Activity Bar + VS 的 Auto Hide 的组合——用户要的"点击显示再点击隐藏"= Activity Bar 行为，`📌`/悬停 = VS Auto Hide 行为，两者都保留。

### 21.3 页签位置可配置（上 / 下 / 左 / 右）

用户要求："这块区域的标题可以设置成显示在上方或下方之类的"。落成配置项：

```jsonc
// layout.json 里每个 TabGroup 一段
{ "type": "Tabs", "tabStrip": "bottom",   // top | bottom | left | right
  "compact": false,                        // true = 只显示图标，不显示文字（窄面板用）
  "overflow": "scroll",                    // 页签过多时：scroll(横滚) | menu(收进 » 下拉)
  "active": "property" }
```

- 默认：**左侧/右侧工具窗口页签条在顶部，底部输出面板页签条在底部**（符合 VS 与易语言双方的直觉）。
- 用户可在面板标题栏右键菜单切换：`页签位置 → 上 / 下 / 左 / 右`；竖排（left/right）时文字旋转 90°。
- 页签条底部时，面板标题（图标 + 名称）仍保留在顶部，避免"不知道这是哪个夹"。
- 页签过多：`scroll` 模式用左右小箭头 + 横滚；`menu` 模式收进末尾 `»`。
- 页签右键菜单：关闭、关闭其他、关闭右侧、浮动、PIN、页签位置、紧凑模式。
- 全部状态写进 `layout.json` 并随布局持久化/还原。

### 21.4 面板内容清单（本期做 UI，数据假）

| 夹/工具窗口 | 页签 | 内容 |
|---|---|---|
| 工作夹（左） | 程序 / 支持库 | 「程序」= 程序数据树（程序集/窗口/子程序/数据类型/常量/资源/模块引用）；「支持库」= 列表 + 启用勾选 |
| 组件箱（左） | — | 搜索 + 分类 + 图标网格/列表（拖拽源，见 5.8） |
| 属性（右） | 属性 | 分组表 + 6 类值编辑器（见 5.9） |
| 输出（底） | 输出 / 事件 / 查找结果 | 分级着色 + 跟随输出 + 双击跳转（见 6.3） |
| 文档区（中） | 每个文档一个页签 | 本期只有 `Form1` 设计器（见第 5 章） |

### 22.3 尺寸、DPI 与缓存

- 逻辑尺寸档：**16 / 20 / 24 / 32 / 48 / 64 DIP**（菜单/树 16，工具条 16~20，组件箱 32，大图标 48~64）。
- 物理需求 = `逻辑尺寸 × dpiScale`；**取 ≥ 需求的最小可用档**，再高质量缩小；**禁止把小于需求的图放大**。
- **优先 SVG**：D2D 侧用 `ID2D1PathGeometry`（推荐，任意 DPI 都锐）或"按目标像素栅格化一次后缓存位图"。无 SVG 才走 PNG 阶梯。
- 缓存 key = `(逻辑名, 逻辑尺寸, dpiScale, 主题变体, 状态)`；`WM_DPICHANGED` 与主题切换时清缓存重建。
- 单色图标（如实现为几何路径）允许在渲染时用 `accent`/`text.secondary` 着色；**彩色图标禁止改色**，禁用态只用 `opacity 40%`。

## 23. 字体与配色设置（设置窗口完整规格）

> 用户指令："各个板块的字体、字体颜色要在设置里可以设置：菜单字体大小/字体、状态夹、程序、属性、UI 上的字体；不足的你补充，像输出界面的字体、大小、颜色、背景等。"

### 23.1 硬约束（架构层面，先立规矩）

1. **一切字体/颜色/尺寸只从 `theme::Tokens` 取**。控件代码里禁止出现字体名、字号、`0xAARRGGBB` 字面量。review 时 grep：`"Segoe UI"`、`"Microsoft YaHei"`、`D2D1::ColorF(0x` 出现在非 `theme/` 目录即算违规。
2. **优先级**：用户 `settings.json` 覆盖 > 主题默认（第 7 章令牌）> 代码兜底。用 `null` 表示"继承上一级"。
3. **改完立即生效，不重启**：`ThemeManager::Set` → 发 `ThemeChanged{区域}` → `TextCache` 按区域失效 → 受影响面板重排 + 重绘。
4. **可回滚**：确定/应用/取消三键语义（取消 = 回滚到打开设置前的快照）。
5. **文本度量缓存**：`TextCache` 的 key 必须包含 `(字体族, 字号, 字重, 行高倍数, dpiScale, 区域)`，否则改字号后行高不更新。
6. **高对比度**：系统开启高对比度时，自定义前景/背景**禁用并灰掉**（不许让用户做出看不见的界面），字体族/字号仍可调。

| `docs/开发文档.md` | 规格与施工图（做什么、怎么做、验收标准） | 只在**规格变更**时改 | 用户改需求 / 发现规格写错 |
| `docs/progress.md` | 进度台账（P0~P22 状态、当前阻塞、下一步） | 开发者 | **每完成一个可运行子步骤立刻改** |
| `docs/handoff.md` | 交接快照（六问） | 交班前的那个人 | 每次交接 / 每次换会话 |
| `docs/pitfalls.md` | 踩过的坑（现象→原因→对策） | 开发者 | **踩到就记，当场记** |
| `docs/open-questions.md` | 等用户拍板的问题 | 开发者 | 一出现就记，交付时一并问 |
| `docs/decisions/ADR-xxxx.md` | 架构决策（一个决策一份） | 开发者 | 做出决定的当天 |
| `docs/parts/Pxx-*.md` | 每个 Part 的交付记录（含截图路径、脚本、证据） | 开发者 | 交付该 Part 时 |
| `docs/changelog.md` | 一行式变更流水 | 开发者 | 每次提交前 |

### 24.3 触发点与时限（"实时"的具体定义）

| 触发点 | 必须做的落档动作 | 时限 |
|---|---|---|
| 开始一个 Part 前 | `progress.md` 里把该 Part 标 🔄，写一句"本次范围" | 动手前 |
| 每完成一个能编译、能跑的小步骤 | 更新 `progress.md` 的备注（做到哪、卡在哪） | **≤30 分钟一次，禁止攒到天黑** |
| 做出任何架构/命名/协议选择 | 新建或追加 ADR | 当天 |
| 踩坑并解决 | `pitfalls.md` 加一行 | **当场** |
| 遇到要用户拍板的问题 | `open-questions.md` 加一行，并在交付说明里问 | 当场 |
| 交付一个 Part | 写 `parts/Pxx-*.md` + `changelog.md` 一行 + `progress.md` 状态改 🔄 | 交付前 |
| 用户确认 | `progress.md` 改 ✅ + 填确认日期 + Git tag | 收到确认后立刻 |
| 换会话 / 交接 | 填 `handoff.md`（六问全答） | 交接前 |

**硬规则：不落档 = 没做。** 代码写完了但台账没更新，视为该 Part 未交付。

### 24.4 三个必用模板

**① Part 交付记录**（`docs/parts/P04-工具栏.md`）：
```markdown
# P04 工具栏 · 2026-11-08
## 范围（3 句话内）
## 新增/变更接口（头文件 + 接口名 + 中文注释）
## 截图（100/125/150/200% 四张 + 路径）
## 自动化证据（.uiscript 内容 + 实际输出 + bridge.log 3~5 条）
## 已知未做 / 已知问题（不许写"无"）
## 下一步候选（等用户确认）
```

**② ADR**（`docs/decisions/ADR-0002-xxx.md`）：
```markdown
# ADR-0002 · 标题
- 状态：提议 / 已接受 / 已废弃
## 上下文（什么问题逼着要做决定）
## 决策（选了什么）
## 备选与否决理由（至少两个备选）
## 后果（正面 / 代价 / 风险）
```

**③ 交接快照**：见 `docs/handoff.md`，六问原样填，历史交接往下追加不删除。

### 24.5 写作规范

- **一条一事**：`pitfalls.md` 一行一个坑，别写成散文。
- **写依据，不写形容词**：✗"性能不错" → ✓"1000 节点滚动 58fps（`ui.perf.fps` 实测）"。
- **写路径、写命令、写数字**：截图给绝对路径，脚本给文件名，验收给阈值。
- **不写"已完成"三个字了事**：必须附证据（截图 / 脚本输出 / 日志行）。未验证的功能写"未验证"。
- **不删历史**：旧交接、旧决策、废弃方案都留着（改成"已废弃 + 原因"），后来人能看懂为什么绕了路。
- **不抄规格**：规格在 `开发文档.md`，其他地方只引用章节号（如"见文档 §5.7"）。

### 24.6 Git（有仓库之后）

- 分支：`part/P04-toolbar`；每个 Part 一个 tag：`P04`。
- 提交信息：`P04: 工具栏分组与溢出`（Part 号开头，一句话说清动词）。
- 每个 Part 至少 **2 次提交**：先"接口 + 空实现 + 文档"，再"实现 + 证据"。这样回滚干净。
- **未确认的 Part 不许 merge 到 main。**

### 24.7 反面例子（见到就算返工）

- ❌ 一口气做完 5 个 Part，最后才写文档 → 用户看不出进度，返工成本翻倍。
- ❌ `progress.md` 里写"工具栏做完了"，但没有截图、没有脚本输出 → 无法验收。
- ❌ 同一个坑踩两次、`pitfalls.md` 里没有 → 说明记录形同虚设。
- ❌ 交接时只有一句"代码在 src/ 里" → 新 AI 要从零读代码重建上下文。
