## 3. IDE 侧要改的三处（main.cpp）

### 3.1 组件加载：合并公共事件与公共方法

组件头现在 `#include "公共事件.h"` / `#include "公共方法.h"`。若解析器只认「本文件内的 SULANG_MFC_* 宏」，需改成：

```
解析某组件 .h 时：
    props   = 本文件 SULANG_MFC_PROPERTY
    events  = 公共事件.h 的 13 条 + 本文件 SULANG_MFC_EVENT
    methods = 公共方法.h 的 295 条
```

判据：属性页事件区显示 14 条（13 通用 + 自身 1），方法区 295 条。

### 3.2 打开 .e：显示"全部可用事件 / 方法"，已绑定的打勾

当前实现是"XML 里有什么就显示什么"，所以五子棋的标签只显示 1 个 `反馈事件`。改成：

```
列表 = 支持库全量事件（3.1 的结果）
foreach XML 里 <控件.事件 名称="X"> ：
    命中则标记「已绑定」并载入该事件的用户代码
未命中的条目保留显示，只是没有代码（双击即新建事件子程序）
```

这同时解决"别人的 .e 打开后事件空空"的观感问题。

### 3.3 支持库页：读取 elib 的「成员命令」分类

新 elib 末尾追加：

```
@分类 成员命令
@命令 取窗口句柄
英文名=GetHWnd
返回=整数型
说明=组件成员命令：取出本窗口或窗口组件的窗口句柄（即HWND）
```

若现解析器假定"@分类 之后都是顶层命令"，无需改；只需确认不会把「成员命令」当普通命令写进语句提示（可选：按分类做过滤/分组显示）。

## 5. 已知限制（不要当成 bug）

1. **成员命令的"归属"**（2026-11-09 修正）：**krnln 是标了归属的**——每个 `.数据类型` 段的 `.成员命令` 块就是该类型自己的方法表，跟 `.命令 分类=成员命令` 块靠 `命令索引` 一一对应（295 条无重复、无多归属）：窗口 23、编辑框 1、画板 28、打印机 32、数据源 71、外部数据库 19…**不要把 295 条全挂到「窗口」**（原版窗口只有 23 条，「打开/关闭」属于数据库/外部数据库）。生成器现在给 `公共方法.h` 每条写 `// @type <类型>`，IDE 按它分发到 数据类型 → <类型> → 方法。
2. **方法/事件的英文标识**：`SULANG_MFC_METHOD(m0001)` 是序号占位，真实英文名在 `// @description` 上方的 `@name` 行；若 IDE 用英文标识做绑定键，需改成「名称→标识」映射（建议直接用中文名做键，避免与 XML 绑定名不一致）。
3. **事件参数**：`公共事件.h` 的参数暂为空（fne 里未导出参数表）。`按下某键`（键代码）、`字符输入`（字符代码）、`反馈事件`（参数一/参数二）是已知有参的，需后续从 fne 或真机确认后补。
4. **数据类型 / 常量**：仅为 `data_types.txt` / `constants.txt` 数据文件，IDE 目前没有加载它们的段落；要真正生效需在 elib 解析器加 `@数据类型` / `@常量` 两段（工作量约半天）。
5. **实现层**：本施工图只补"元数据"（名称/签名/说明）。295 条方法、451 条缺失命令的 C 实现仍是自研工作量，`libcore_support.a` 现有 295 个符号需逐条对表。
