# P3 菜单栏 · 易语言真实菜单（含多级下拉）

> ⚠️ **2026-11-06 重置**：本记录对应的实现已全部删除，状态记为 **⬜ 未实现**。
> 文字只作为「做过什么、坑在哪」的参考保留，不要当成已完成的工作继续叠加。

> 目标：菜单不是"仿"，而是**易语言 5.95 的真实菜单树**；外观按 VS 2026 深色。鼠标悬停即展开子菜单、二级菜单再展开孙子菜单。

## 1. 数据来源（不靠人工抄、不靠自动化点击）

易语言主菜单是**自绘**的，`GetMenu` 返回 0，`GetMenuString` 拿不到任何东西（见 `pitfalls.md` L1）。
但菜单定义仍留在 PE 资源里：

```
craft-anything-cli.exe \
  native-pe-resources-list --path "易语言安装目录\e.exe"
```

结果里 `RT_MENU` 共 **17 个**，其中 **id=127**（4558 字节）就是完整的主菜单栏，
按文件顺序保存了 10 个顶级菜单及其全部层级。

解析脚本（自写，纯字节级，无第三方依赖）：

- `tools/parse-menu-text.ps1` — 把 RT_MENU 里的 UTF-16 串按顺序抽出来 → `tools/out/e-menus2.txt`
- 每个菜单项前的 2 字节是 `mtOption` 标志位，会被误读成一个汉字（如 `耏&N.现行单元`），
  实现时按下表剥离。

导出的原始清单直接落到 `tools/out/e-menus2.txt`，可重复生成。

## 3. 代码结构

| 文件 | 职责 |
|---|---|
| `src/shell/menu.h` | `MenuItem` / `MenuBarItem` 模型；`MenuCaption()` 生成 `F.程序` 这类显示文本 |
| `src/shell/menu.cpp` | 全部菜单数据（唯一真源），可在不改绘制代码的前提下增删项 |
| `src/shell/menu_ui.h/.cpp` | `MenuState`（开了哪个、每层悬停在哪）+ `BuildMenuGeometry()` 算出菜单栏与每级面板矩形 |
| `src/shell/painter.cpp` → `MenuPopups()` | 按几何绘制下拉：圆角面板、悬停底、勾选、灰显、右对齐快捷键、子菜单箭头 |
| `src/app/main_window.cpp` | `WM_MOUSEMOVE` / `WM_LBUTTONDOWN` / `WM_KEYDOWN(ESC)` / `WM_NCHITTEST` |

关键点：**绘制与命中测试共用同一份 `MenuGeometry`**，不会出现"看得见点不中"。

## 4. 交互行为（已验证）

- 悬停顶级菜单：底衬高亮；若已有菜单打开，自动切换。
- 点击顶级菜单：打开 / 再点关闭。
- 悬停下拉项：高亮 + 该项有子菜单时**立即展开下一级**。
- 点击有子菜单的项：展开下一级，不关闭。
- 点击普通项：回调 `onMenuCommand(caption)`（当前写入状态栏「已选择：O.打开」），收起全部。
- 点面板外 / `ESC`：收起。
- 打开时 `SetCapture`，点窗口外也能正确关闭。

## 6. 与真易语言的差异（有意为之）

1. **深色**：易语言是浅色，本项目按用户要求走 VS 2026 深色。
2. **加速键**：易语言把字母直接印在文字里（`N.新建`），本实现完全照搬，未改成下划线式。
3. **黑月相关项**：用户机器上装了「黑月」支持库，`编译` 菜单多出 `黑月静态编译` 等项；
   资源里的官方菜单没有这些，属第三方注入，暂不纳入。
4. **最近文件**：真机是真实 MRU（8 条），当前为占位 3 条灰显，等文件系统接上再动态生成。
